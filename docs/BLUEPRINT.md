## Summary

- **ปัญหา:** คนหน้าเครื่อง Spray Dryer ต้องจดค่า Tin, Tout, อัตราป้อน และเวลาด้วยมือ ทำนาย Tout ก่อนรันยาก และตรวจย้อนหลังไม่ได้ว่าค่าไหนวัดและค่าไหนทำนาย `[brief]`
- **เป้า:** ลดรอบทดลองที่ไม่จำเป็น ลดการกรอกด้วยมือ ฟังก์ชันสำคัญกว่าความสวย `[brief]`
- **ขอบเขตรอบนี้ (MVP สำหรับ TED):** เว็บตัวอย่างระยะ A ของบรีฟ (คลิกได้บนข้อมูลสมมติ) พร้อมหน้าก่อน–ระหว่าง–หลังทดลอง, ประวัติอ่านอย่างเดียว, ป้ายที่มาครบ 9 ชนิด, ETA ตามเกณฑ์ที่ตกลงไว้, มาสคอตและอากาศ `[user]`
- **ไม่อยู่ในรอบนี้:** ระยะ B (แอปจริงที่เรียกสูตรผ่าน adapter), ระยะ C (ฐานข้อมูลงานวิจัย, Snap-to-Read, Machine ID, แดชบอร์ดผู้บริหารเต็ม), Calibration, Optimizer, DOE, Firebase, backend `[brief]` `[user]`
- **ความเสี่ยงหลัก:** (1) ข้อกำหนดขัดกันระหว่างบรีฟกับคำตอบที่ตกลงแล้ว (ดูหัวข้อ 2) (2) ไฟล์สูตรสองชุด ชุดที่เจ้าของส่งมามีค่าคาลิเบรตจริง (3) ข้อมูลจริงยังไม่มา (4) มี 3 ชุดโค้ดที่ไม่ตรงกัน
- **Stack:** Vite + React + TypeScript + localStorage (key `proto_`) ไม่มี backend `[user]` ต่างจากบรีฟที่ตั้งค่าเริ่มต้นเป็น Next.js + Firebase `[brief]` ซึ่งยอมให้เลือกอย่างอื่นถ้ามีเหตุผล (ข้อ 11.4)

## 1. ปัญหาและเป้าหมาย

- **ใคร มีปัญหาอะไร:** ผู้ปฏิบัติงานหน้าเครื่องจดค่าซ้ำและช่องกรอกเยอะ (ตามบรีฟ หน้า Console เดิมมี id ราว 409 ตัวและช่องกรอก 248 ช่อง) ทีมตรวจย้อนหลังไม่ได้ว่าค่าไหนวัดจริง `[brief]`
- **สำเร็จเมื่อ (ตรวจได้):**
  1. ผู้ใช้ใหม่เริ่มรันแรกได้โดยกรอกเฉพาะช่องที่ขั้นนั้นต้องใช้ `[assumed]` ยังไม่มีตัวเลข baseline `[open]`
  2. ทุกตัวเลขมีป้ายที่มาหนึ่งป้ายจาก 9 ชนิด และค่าว่างแสดงเป็น "ยังไม่มีค่า" `[brief]`
  3. ผู้บริหารเห็นเฉพาะสรุปรันที่ปิดแล้ว `[feedback]`

## 5. กติกาทางธุรกิจ (Business Rules)

ทุกข้อใช้กับทุกหน้า ห้ามฝ่าฝืน

- **BR-01 ค่าว่างไม่ใช่ 0:** ค่าที่ไม่มีแสดงเป็น "ยังไม่มีค่า" พร้อมป้าย MISSING และห้ามเป็น 0 ใน CSV, JSON, กราฟ `[brief 5.1]`
- **BR-02 TS ไม่เท่ากับ °Brix:** ใช้ Brix ได้เมื่อผู้ใช้เลือกเองและติดป้าย PROXY `[brief 5.2]`
- **BR-03 Pump % ไม่ใช่อัตราป้อนจริง:** ETA L1 ใช้ ปริมาตรที่เหลือ ÷ อัตราป้อนจริง (mL/min) เท่านั้น `[brief 5.3]` `[user]`
- **BR-04 หนึ่งตัวเลขมีป้ายเดียว:** ป้ายทั้ง 9 ชนิด ห้ามปนกัน `[brief 5.4]`
- **BR-05 Target Tout:** ผลเป็น "คำนวณ UNVALIDATED" เสมอ ฟิลด์ recommendations เป็น [] และ operationallyApproved เป็น false `[brief 5.5]`
- **BR-06 predictionError ว่างจนกว่าจะมีค่าวัดจริง** `[brief 5.6]`
- **BR-07 รายงานผูกกับรันเดียว:** ห้ามนำค่าทำนายของรันใหม่ไปคู่ผลแล็บของรันเก่า `[brief 3.3]`
- **BR-08 สถานะรันเปลี่ยนเมื่อผู้ใช้กดเท่านั้น และรันปิดแล้วแก้ไม่ได้** ทำสำเนาเป็นร่างได้ `[PROMPT 4]`
- **BR-09 ETA L2 แสดงเมื่อมีรันปิดแล้วของเครื่องเดียวกันอย่างน้อย 3 รัน** Admin ตั้งได้ ติดป้าย ASSUMED `[PROMPT 5, user]`
- **BR-10 ติ๊ก ✓ เฉพาะขั้นที่ทำงานจริง** การเปิดดูเฉย ๆ ไม่ติ๊ก ประวัติและรายงานไม่มี ✓ `[brief 3.3]`
- **BR-11 ข้ามขั้นได้และกลับมากรอกย้อนหลังได้** ระบบห้ามบังคับลำดับ `[brief 3.3]`
- **BR-12 ร่างเก็บอัตโนมัติ** เปิดใหม่ต้องมีแถบกู้ร่างพร้อม "ใช้ร่างนี้" และ "ทิ้งร่าง" `[brief 3.3]`
- **BR-13 ช่วงพักไม่นับเป็นเวลาป้อนจริง** `[feedback 5]`
- **BR-14 ห้ามใช้ค่า calibration จริงและผลทดลองจริงในโค้ด ตัวอย่าง หรือเอกสาร** ใช้ข้อมูลสมมติและเขียนกำกับว่า "ข้อมูลตัวอย่าง" `[brief หัวเรื่อง]`
- **BR-15 ผลประเมินที่ใช้สูตรสมมติต้องเขียนว่า "ค่าตัวอย่างสมมติ ไม่ได้คำนวณจากสูตรจริง"** `[brief 5.9]`
- **BR-16 ความคลาดเคลื่อนราว 5 °C เป็นแนวอ่านผล ห้ามเคลมว่าแม่น** `[brief 5.10]`

## 6. User stories และ Use cases

### 6.1 Stories (Must)

- **US-01 เลือกโหมดผู้ใช้:** As a นักศึกษา, I want เลือกโหมดตอนเริ่ม, so that เห็นตัวอย่างที่เหมาะกับฉัน
  - Given เปิดครั้งแรก / When เลือกโหมด / Then เมนูและตัวอย่างเปลี่ยน แต่การคำนวณเหมือนกันทุกโหมด
  - Error: ไม่เลือก → ใช้โหมดเริ่มต้น และบอกว่าเปลี่ยนได้ที่ตั้งค่า
- **US-02 จดค่าเป็นจุด:** As an operator, I want จด Tin และ Tout พร้อมเวลาทีละจุด, so that ไม่ต้องจำเวลา
  - Given รันอยู่ / When กดจดค่า / Then เก็บเป็นจุดแยกและแสดงค่าที่เพิ่งจด
  - Error: กรอกตัวอักษร → ข้อความบอกช่องที่ผิดและไม่บันทึก
  - Edge: จดสองจุดในวินาทีเดียวกัน → เก็บทั้งคู่
- **US-03 บันทึกเหตุการณ์และสถานะย่อย:** As an operator, I want บันทึก Warm-up, Feeding, Pause, Resume, Post-feed และเหตุการณ์ผิดปกติ, so that ค่าผิดปกติอธิบายได้
  - Edge: Pause ไม่นับเวลาป้อนจริง (BR-13)
- **US-04 ETA:** As an operator, I want เห็นเวลาที่เหลือพร้อมป้ายที่มา, so that รู้ว่าค่าไหนแผนและค่าไหนประมาณ
  - L1 ตาม BR-03, L2 ตาม BR-09
  - ข้อมูลไม่พอ → "ยังประมาณไม่ได้" ไม่ใช่ 0
- **US-05 ปิดรัน:** As a reviewer, I want ใส่ผลแล็บและปิดรัน, so that รันเสร็จและทบทวนได้
  - Error: ปิดทั้งที่ไม่มีค่าที่จด → เตือนและยังปิดได้ (รายงานไม่มี Tout ที่อ่านได้)
- **US-06 ทำนาย Tout:** As a นักวิจัย, I want ทำนาย Tout ก่อนรัน, so that เลือกพารามิเตอร์ได้ดีขึ้น
  - ผลเป็น PREDICTED และ UNVALIDATED ตาม BR-05
  - Error: อินพุตไม่ครบ → "คำนวณไม่ได้" พร้อมเหตุผลจาก adapter
  - Edge: อุณหภูมิต่ำกว่า T_FLOOR (25 °C) → ระบบบอกว่าโมเดลไม่ valid
- **US-07 ผู้บริหารดูสรุป:** As an executive, I want ดูสรุปรันที่ปิดแล้วอย่างเดียว, so that ไม่เห็นข้อมูลดิบ
- **US-08 Admin จัดการเครื่อง:** As an admin, I want เพิ่ม แก้ ลบเครื่อง และดูบันทึกการใช้งาน, so that ควบคุมทะเบียนได้
  - Error: ชื่อสั้นกว่า 2 ตัวอักษร → ข้อความชัด ไม่บันทึก
- **US-09 อากาศและมาสคอต:** As a ผู้ใช้ทุกคน, I want เห็นสภาพอากาศของเครื่อง, so that ระบบเป็นมิตร
  - ให้สิทธิ์ GPS → ปัดเป็นจังหวัด → เรียกบริการอากาศ → เลือกท่ามาสคอต
  - Error: ปฏิเสธ GPS → เลือกจังหวัดเอง; บริการล่ม → ท่าเป็นกลางและบอกว่าไม่มีข้อมูลอากาศ
- **US-10 ประวัติอ่านอย่างเดียว:** As a reviewer, I want เปิดประวัติดูได้โดยไม่แก้รันเงียบ ๆ
  - การแก้ค่าย้อนหลังต้องมีเหตุผลและบันทึก `[open]` (7.3 ข้อ 5)
- **US-11 กู้ร่าง:** As an operator, I want กลับมาต่อรันที่ค้างได้ เมื่อปิดแท็บหรือไฟดับ
  - BR-12

## 9. โครงและการไหลของข้อมูล

- **User flow หลัก (จดค่า):** ภาพรวม → เลือกรันที่กำลังเดิน → กด "จดค่า" → กรอก Tin, Tout (ค่าก่อนหน้าเติมให้) → บันทึก → ETA อัปเดต → ปิดรันเมื่อครบ
- **Data flow:** ผู้ใช้ → React → repository (interface เดียว) → localStorage
- **การทำนาย:** React → `src/core/adapter.ts` → `physics.gen.js` (อ่านอย่างเดียว)
- **อากาศ:** React → GPS (ปัดเป็นจังหวัด) → Open-Meteo → React (ไม่มีข้อมูลรันออกไป)

**Architecture:** เลือกแบบเรียบง่ายที่สุด

| ตัวเลือก | ความซับซ้อน | ค่าใช้จ่าย | ความปลอดภัย | เรียนรู้ | ความเร็ว |
|---|---|---|---|---|---|
| A: Vite + React + localStorage (โค้ดเดิม) | ต่ำ | 0 | ต่ำ (ในเครื่อง) | รู้แล้ว | เร็วสุด |
| B: Next.js + Firebase (บรีฟ) | สูง | ต้องแผน Blaze | สูง | ต้องเรียนใหม่ | ช้า |
| C: Next.js + PostgreSQL | สูง | ต้องหาเซิร์ฟเวอร์ | สูง | ต้องเรียนใหม่ | ช้า |

**แนะนำ A** ตามที่คุณเลือก `[user]` สิ่งที่ยอมเสีย: ไม่มีการยืนยันตัวตนจริง ไม่มีสิทธิ์ที่ server ข้อมูลอยู่ในเครื่องเดียว ไม่มีการแชร์ระหว่างทีม รายการนี้ต้องบอกคณะกรรมการตรง ๆ `[assumed]`
