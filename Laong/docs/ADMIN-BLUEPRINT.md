# Blueprint สำหรับ Laong Admin

## Summary

[user] ให้ Admin เห็นกิจกรรมของผู้ดูแล จัดการผู้ใช้ แยกทะเบียนเครื่องตามสถาบันหรือบริษัท และอัปโหลดเอกสารสูตรพร้อมตั้งชื่อได้

[verified] ห้าภาพมาจากหน้า Admin Preview ใน `public/laong-assets/previews.js` ตารางผู้ใช้ เครื่อง และ Audit ใช้ข้อมูลสังเคราะห์ กิจกรรมล่าสุดกับบันทึกการใช้งานอ่านจากชุดข้อมูลเดียวกัน ทะเบียนเครื่องที่ใช้จดรันในเดโมเก็บในเบราว์เซอร์ ส่วนหน้าเอกสารสูตรแสดงสถานะรอไฟล์โมเดล

[assumed] เริ่มจากบัญชีและองค์กร แยกสิทธิ์ผู้ดูแลแพลตฟอร์มกับผู้ดูแลองค์กร แล้วเชื่อมทะเบียนเครื่อง รัน และเอกสารกับองค์กรเจ้าของข้อมูล ใช้ Auth, Database และ Object Storage ที่ตรวจสิทธิ์ฝั่ง Server

## 1. Problem and goal

[user] ผู้ดูแลต้องรู้ว่าใครทำอะไรกับบัญชีหรือเครื่อง เวลาใด และเครื่องนั้นอยู่ที่ไหน [assumed] ตรวจรับได้เมื่อผู้ดูแลเปิดรายการขององค์กรตนเองได้ เปิดขององค์กรอื่นไม่ได้ และทุกการจัดการสำคัญมีรายการให้ตรวจย้อนหลัง

## 2. Scope

- [user] Must แสดงบัญชีและจัดการรีเซ็ตรหัส ระงับ และลบตามสิทธิ์ แสดงผู้ทำรายการ เวลา เป้าหมาย และผู้รับผิดชอบ แยกเครื่องตามองค์กร และอัปโหลด PDF, Markdown และ Excel พร้อมชื่อเอกสาร
- [assumed] Should ค้นและกรองตามองค์กร สถานะบัญชี ห้องแล็บ และช่วงเวลา
- [assumed] Later ทีมย่อย การแชร์เครื่องข้ามองค์กร และการนำสูตรเข้าเครื่องคำนวณหลังตรวจวิธีคำนวณและเวอร์ชัน

## 3. Users and roles

| Role | ดูและจัดการ |
| --- | --- |
| Platform Admin [assumed] | เห็นบัญชีทุกองค์กรเพื่อดูแลแพลตฟอร์ม ระงับบัญชีระดับแพลตฟอร์มและจัดการคำขอลบตามสิทธิ์ |
| Org Admin [assumed] | เห็นและจัดการสมาชิก เครื่อง และไฟล์ในองค์กรตนเอง ระงับการเข้าถึงเฉพาะองค์กร |
| Member [assumed] | ใช้เครื่องและเปิดเอกสารที่ได้รับสิทธิ์ในองค์กร |

## 4. User stories and use cases

| Story | ลำดับและเกณฑ์ตรวจรับ |
| --- | --- |
| US-01 [user] ติดตามกิจกรรม | Admin เปิดภาพรวมแล้วกดดูประวัติทั้งหมด เห็นผู้ทำรายการ เวลา เป้าหมาย ผล และผู้รับผิดชอบถ้ามีการมอบหมาย ถ้าไม่มีรายการให้แสดงสถานะว่าง |
| US-02 [user] จัดการบัญชี | Admin ค้นบัญชี → ยืนยันการส่งลิงก์รีเซ็ตหรือระงับพร้อมเหตุผล → เห็นผลและประวัติ เมื่อการส่งล้มเหลวแสดงสถานะล้มเหลว [assumed] การลบถาวรเป็นกระบวนการแยกตามนโยบายที่ตกลง |
| US-03 [user] จัดเครื่องตามสถาบัน | Admin เลือกองค์กร → กรองห้องแล็บ → เปิดเครื่องและรันที่ผูกกัน หากไม่มีสิทธิ์ฝั่ง Server ปฏิเสธคำขอ |
| US-04 [user] เก็บสูตร | Admin ตั้งชื่อ → แนบ PDF, MD หรือ XLSX → เห็นเวอร์ชันและเปิดไฟล์ได้ตามสิทธิ์ หากไฟล์ผิดประเภทหรืออัปโหลดล้มเหลว แจ้งให้เลือกไฟล์ใหม่หรือลองอีกครั้ง |

## 5. Requirements

- FR-01 [assumed] ใช้ Audit Log ชุดเดียวทั้งสรุปล่าสุดและประวัติเต็ม บันทึกจาก Server และเก็บผู้ทำรายการแยกจากผู้รับผิดชอบงาน (US-01)
- FR-02 [assumed] ให้ผู้ใช้ตั้งรหัสเองผ่านลิงก์ใช้ครั้งเดียวที่หมดอายุ จัดการ session เมื่อระงับบัญชี และบันทึกผลการดำเนินการ (US-02) [OWASP Password Reset](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)
- FR-03 [assumed] ผูกเครื่องกับองค์กรและห้องแล็บ ให้ Machine ID ใช้ซ้ำต่างองค์กรได้โดยมีรหัสภายในที่ไม่ซ้ำ (US-03)
- FR-04 [assumed] เก็บชื่อ ผู้ส่ง เวลา เวอร์ชัน และไฟล์ ตรวจสิทธิ์ทั้งการอัปโหลดและดาวน์โหลด และตรวจประเภทกับขนาดไฟล์ฝั่ง Server (US-04) [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- NFR-01 [assumed] ตรวจขอบเขตองค์กรทุกคำขอ รวมถึงไฟล์และ Audit Log หลีกเลี่ยงรหัสผ่านและ Reset Token ในประวัติ

## 6. Data and flow

[assumed] Organization เก็บชื่อและประเภท เช่น บริษัท โรงเรียน หรือมหาวิทยาลัย ส่วนห้องแล็บเก็บสถานที่ภายในองค์กร บัญชีเชื่อมองค์กรผ่าน Membership ซึ่งเก็บบทบาทและสถานะ จึงรองรับคนเดียวที่อยู่หลายองค์กรได้ เครื่องผูกองค์กรและห้องแล็บ รันอ้างอิงรหัสเครื่องภายใน เอกสารมีเวอร์ชันและเก็บไฟล์ใน Object Storage Audit Event เก็บผู้กระทำ องค์กร เป้าหมาย เวลา และผล

[assumed] แนะนำเริ่มจากองค์กรและห้องแล็บ เพราะใช้กำหนดขอบเขตข้อมูลได้ทันที การเพิ่มทีมตั้งแต่แรกช่วยแบ่งงานย่อย แต่ต้องกำหนดสมาชิกและสิทธิ์เพิ่มทุกระดับ

## 7. Risks, assumptions and open questions

- [open] ยืนยันว่าผู้ดูแลแพลตฟอร์มเห็นบัญชีทั้งหมด และผู้ดูแลองค์กรเห็นเฉพาะสมาชิกของตน
- [open] ตกลงเกณฑ์ลบถาวรและข้อมูลที่ต้องเก็บเมื่อบัญชีเคยจดรันหรืออัปโหลดเอกสาร [assumed] เริ่มจากระงับหรือถอดสิทธิ์
- [open] ยืนยันว่าเอกสารสูตรรอบแรกใช้เปิดอ่านและดาวน์โหลด [assumed] การเปิดใช้ในระบบคำนวณเป็นงานภายหลัง
- [open] ผู้ให้บริการ Auth, Database, Object Storage และวิธีย้ายข้อมูลเดโมที่ต้องการเก็บ

## 8. Test and done

- [assumed] ทดสอบสิทธิ์ด้วยบัญชีจากสององค์กร รวมถึงเปิด URL เครื่อง รัน เอกสาร และ Audit ของอีกองค์กรโดยตรง
- [assumed] ทดสอบลิงก์รีเซ็ตที่ใช้แล้วและหมดอายุ ระงับบัญชีที่มี session ค้าง และยืนยันว่ารันเก่ายังเปิดย้อนหลังตามสิทธิ์
- [assumed] ทดสอบอัปโหลดทั้งสามชนิด ไฟล์ผิดประเภท และการอัปโหลดซ้ำเป็นเวอร์ชันใหม่

1. [assumed] ทำ Auth, Organization, Membership และ Audit พื้นฐาน ตรวจขอบเขตสิทธิ์ด้วยสององค์กร
2. [assumed] เชื่อมหน้าผู้ใช้และทะเบียนเครื่อง เพิ่มการค้นหาและประวัติผู้ดูแลจากข้อมูลจริง
