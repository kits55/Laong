## 1. Problem and goal

- [user] ผู้ทำงานวิจัยและพัฒนาผลิตภัณฑ์ที่ต้องออกแบบวิธีทดลองเองต้องการบันทึกข้อมูลตลอดการทดลองและออกรายงานจากที่เดียว
- [หลักฐาน] การทำงานที่รู้ตอนนี้มาจากข้อความของปลื้มและต้นแบบเดิม ต้องดูตัวอย่างการทำงานจริงเพื่อรู้ว่าข้อมูลอยู่ในเครื่องมือใด ใครกรอก และช่วงไหนต้องกรอกซ้ำ
- [assumed] วัด Pilot จากจำนวนจุดที่ต้องคัดลอกข้อมูล เวลาจากสิ้นสุดรันถึงได้รายงาน และความครบถ้วนของข้อมูลที่ทีมกำหนด [open] เก็บ Baseline จากรันจริงก่อนตั้งเป้า

- [user] รูปแบบรายงานที่ต้องการคือ PDF, Word และ Excel [assumed] เริ่ม PDF สำหรับส่งรายงาน [open] หากทีม Pilot ต้องแก้รายงานหรือวิเคราะห์ข้อมูลในไฟล์ตั้งแต่แรก ให้ขยับ Word หรือ Excel ขึ้นเป็น Must
- [assumed] **Should** ต่อ Tout Prediction สำหรับ Spray Dryer หลังตรวจไฟล์และกรณีทดสอบ ส่วนรูปแบบ Export ที่เหลือส่งตามลำดับการใช้งานจริง

## 6. Data and flow

- [assumed] `TemplateVersion` ระบุช่อง ชนิดข้อมูล หน่วย และช่วงที่ใช้ ส่วน `Run` ระบุทีม ผู้รับผิดชอบ สถานะ เวอร์ชันของ Template แผนและผลสรุป หนึ่งรันมี `LogEntry` ได้หลายรายการ และมี `Prediction` เมื่อ Template รองรับ
- [assumed] ผู้ทดลองกรอกใน Frontend → Server ตรวจสิทธิ์และความถูกต้อง → Database เก็บลงรัน → ผู้มีสิทธิ์เปิดประวัติหรือ Export จากข้อมูลชุดเดียวกัน รูปแบบรายงานอาจต่างกันตามงานที่ผู้ใช้ต้องทำต่อ
- [assumed] สำหรับ Spray Dryer ให้ส่งเฉพาะข้อมูลที่โมเดลต้องใช้ไปคำนวณ เก็บผลแยกจากค่าที่ผู้ทดลองอ่านจากเครื่อง Template ทั่วไปใช้ Flow เดียวกันโดยข้ามขั้นพยากรณ์
- [assumed] **ทางเลือก A: ทำ Spray Dryer อย่างเดียว** กำหนดฟอร์มและส่งมอบได้ง่ายขึ้น แต่การทดลองชนิดถัดไปอาจต้องเขียนฟอร์มและรายงานใหม่
- [assumed] **ทางเลือก B: ใช้ระบบบันทึกร่วมกันและมี Template พร้อมใช้** ต้องออกแบบเวอร์ชันของฟอร์มและทดสอบเพิ่มอีกหนึ่ง Workflow แต่ช่วยพิสูจน์การใช้ซ้ำโดยเริ่มจากขอบเขตที่ดูแลได้ เลือก B สำหรับข้อเสนอ Pilot

- [assumed] ความเสี่ยงหลักคือฟอร์มทั่วไปกรอกแล้วให้ข้อมูลไม่พอทำงาน หรือใช้เวลามากกว่าเครื่องมือเดิม ใช้รันตัวอย่างจากแล็บจริงและเทียบเวลาทำรายงานก่อนกำหนด Scope เพิ่ม
- [assumed] จุดขายที่ต้องพิสูจน์คือทีมใช้เวลาเก็บและส่งต่องานน้อยลงใน Workflow จริง ตั้งต้นที่สอง Template และทดสอบรายงานรูปแบบหลักก่อน
- [open] ปลื้มช่วยเลือกการทดลองชนิดที่สองและส่งตัวอย่างการจดข้อมูลกับรายงานที่ทีมใช้ หากมีแอปอ้างอิง ให้ใช้ดูช่องกรอกและลำดับงาน
- [open] เจ้าของโมเดลช่วยยืนยันไฟล์ เวอร์ชัน ช่วงอินพุตที่ใช้ได้ และกรณีทดสอบที่มีผลคาดหวัง
- [open] ทีม Pilot ช่วยยืนยันว่าใครบันทึก ตรวจ ปิดรันและ Export รวมถึงใช้เครื่องอะไรที่โต๊ะทดลอง
