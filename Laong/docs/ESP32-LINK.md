# ต่อบอร์ด ESP32 กับ Laong (เตรียมไว้ ปิดอยู่เป็นค่าเริ่มต้น)

สถานะ: ฝั่งเว็บเขียนและทดสอบส่วนตัวอ่าน/เขียนข้อความแล้ว (ดู `tests/device.test.mjs`) ฝั่งบอร์ดมีโค้ดตัวอย่างที่ **ยังไม่ได้ทดสอบกับบอร์ดจริง** และยังไม่ได้ลองเชื่อมเว็บกับบอร์ดจริงเลย

## ภาพรวม

```
เว็บ Laong  <-- WebSocket (JSON) -->  ESP32  --> กล้องที่ต่อกับบอร์ด
```

เปิดใช้ได้ที่ ตั้งค่าและช่วยเหลือ > บอร์ด ใส่ที่อยู่ เช่น `ws://192.168.1.50:81` แล้วเปิดสวิตช์ ปิดอยู่จนกว่าจะเปิดเอง ไม่มีการเชื่อมต่อออกนอกเครื่องในตอนที่ปิด

## ขอบเขตที่ตั้งใจ

- เว็บส่งได้เฉพาะ `hello`, `ping`, `status` และคำสั่งกล้อง `cam.start`, `cam.stop`, `cam.snap`
- ไม่มีคำสั่งควบคุม Spray Dryer โค้ดฝั่งเว็บ (`src/device/protocol.ts`) ปฏิเสธการส่งข้อความชนิดอื่น และมีเทสต์ตรวจไว้
- ค่าจากบอร์ดในระยะนี้ใช้แค่สถานะ ไม่ถูกนำเข้าเป็นค่าของรัน การอ่านค่าจากภาพกล้อง (Snap-to-Read) ยังไม่ทำ เพราะยังไม่มีสเปกและยังไม่ได้ตัดสินว่าค่าที่อ่านจากภาพจะติดป้ายอะไร
- ต้องให้ปลื้มยืนยันว่า การให้เว็บสั่งกล้องที่ต่อกับบอร์ด ไม่ขัดกับขอบเขต "ช่วยตัดสินใจ ไม่ควบคุมเครื่อง" (หัวข้อ 12 ของบรีฟ)

## ข้อความ (JSON หนึ่งข้อความต่อหนึ่งเฟรม)

เว็บส่ง

| ข้อความ | ความหมาย |
|---|---|
| `{"t":"hello","app":"laong","v":1}` | ทักทายหลังเชื่อมต่อ |
| `{"t":"ping","id":12}` | เช็กการมีชีวิตและวัดความหน่วง ส่งทุก 5 วินาที |
| `{"t":"status"}` | ขอสถานะ |
| `{"t":"cam.start","run":"R-1105-2358K"}` | เริ่มกล้อง (ส่งเมื่อกดเริ่มจับเวลา และเปิดสวิตช์ "ให้กล้องทำงานพร้อมตัวจับเวลา") |
| `{"t":"cam.stop"}` | หยุดกล้อง (ส่งเมื่อกดจบการจับเวลา) |
| `{"t":"cam.snap"}` | ถ่ายหนึ่งภาพ (ปุ่มทดลองในหน้าตั้งค่า) |

บอร์ดตอบ

| ข้อความ | ความหมาย |
|---|---|
| `{"t":"hello","board":"ESP32","fw":"0.1.0","cam":"ready"}` | ตอบ hello |
| `{"t":"pong","id":12}` | ตอบ ping ด้วย id เดิม |
| `{"t":"status","cam":"ready","uptimeS":340}` | สถานะ |
| `{"t":"cam","state":"busy"}` | สถานะกล้องเปลี่ยน (`none`, `ready`, `busy`, `error`) |
| `{"t":"error","msg":"..."}` | บอร์ดแจ้งข้อผิดพลาด |

ข้อความที่รูปแบบไม่ตรงถูกทิ้งโดยไม่เดาค่า ข้อความยาวเกิน 2,000 ตัวอักษรถูกทิ้ง

## พฤติกรรมการเชื่อมต่อ

- ถ้าไม่ได้ยินอะไรจากบอร์ดเกิน 12 วินาที ถือว่าหลุด แสดงสถานะ ผิดพลาด และลองเชื่อมต่อใหม่เองห่างขึ้นเรื่อย ๆ (2, 4, 8 ... สูงสุด 30 วินาที) จนกว่าจะปิดสวิตช์
- ความหน่วงที่แสดงเป็นค่าที่แอปวัดเอง ติดป้าย Measured ส่วนชื่อบอร์ด เฟิร์มแวร์ และสถานะกล้องเป็นข้อความที่บอร์ดแจ้งมา
- ที่อยู่บอร์ดมาจากผู้ใช้เท่านั้น ไม่มีการสแกนหาบอร์ดอัตโนมัติ

## ข้อจำกัดที่ต้องรู้

- เปิดเว็บแบบ `https` จะใช้ `ws://` ไม่ได้ (เบราว์เซอร์บล็อก) ต้องใช้ `wss://` ซึ่งบอร์ดต้องมีใบรับรอง หรือเปิดเว็บแบบ `http` ในเครือข่ายเดียวกับบอร์ด เช่น `npm run dev` หรือ `npm run preview`
- ติดตั้งเป็นแอปบนมือถือได้ แต่ถ้าเปิดจากโดเมน https ต้องแก้เรื่อง `wss://` ก่อนเสมอ
- บอร์ดต้องอยู่ในเครือข่ายเดียวกับเครื่องที่เปิดเว็บ

## ตัวเลือกอื่นที่พิจารณา

| ทาง | ข้อดี | ข้อเสีย |
|---|---|---|
| WebSocket ผ่าน Wi-Fi (ที่ทำไว้) | ใช้ได้ทั้งมือถือและคอม ไม่ต้องต่อสาย สองทางจริง | ติดเรื่อง https กับ wss |
| Web Serial (USB) | ไม่ต้องมี Wi-Fi เหมาะตอนทดสอบ | ใช้ได้เฉพาะ Chrome/Edge บนคอม ต้องต่อสายกับเครื่องที่เปิดเว็บ |
| Web Bluetooth (BLE) | ไม่ต้องมี Wi-Fi ใช้กับมือถือ Android ได้ | ไม่รองรับ iPhone/Safari ข้อความยาวต้องแบ่งชิ้น |
| MQTT ผ่านเซิร์ฟเวอร์กลาง | บันทึกประวัติได้ ใช้หลายเครื่อง | ต้องมีเซิร์ฟเวอร์ ซึ่งยังไม่ได้ตัดสินเรื่อง backend |

ถ้าภายหลังต้องดึงภาพจากกล้อง ESP32-CAM (สตรีม MJPEG ทาง HTTP) ควรแยกจากช่องสัญญาณนี้ และต้องตัดสินเรื่องป้ายที่มาของค่าที่อ่านจากภาพก่อน
