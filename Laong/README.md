# Laong · SprayDry Copilot (ระยะ A: ต้นแบบคลิกได้)

ข้อมูลทีมลับ ห้ามส่งออกนอกทีม ตัวเลขทั้งหมดในต้นแบบเป็น **ข้อมูลตัวอย่างสมมติ** ไม่ใช่ผลทดลองหรือค่าคาลิเบรตจริง

เว็บที่ติดตั้งเป็นแอปได้ (PWA) ทำงานบนมือถือ แท็บเล็ต แล็ปท็อป และจอตั้งโต๊ะ ใช้ Laong design system ในโฟลเดอร์ `design-system/` และเรียกสูตรจริงใน `physics-model.js` ผ่านชั้นเชื่อมบาง ๆ

## เริ่มใช้งาน

```bash
npm install
npm run dev          # เปิดที่ http://127.0.0.1:5173
npm test             # ตรวจ hash ของสูตร สูตรย้อนกลับ และกฎข้อมูล (15 ข้อ)
npm run verify:copy  # ตรวจว่าไม่มี em dash หรือ en dash ในข้อความหน้าจอ
npm run build        # ตรวจชนิดข้อมูลและสร้างไฟล์ใน dist/ (ติดตั้งเป็นแอปและใช้ออฟไลน์ได้)
npm run preview      # ลองเปิดไฟล์ที่ build แล้วที่ http://127.0.0.1:4173
```

เข้าสู่ระบบด้วยบทบาทตัวอย่างใดก็ได้ ระบบบัญชีจริงยังไม่ได้ตัดสินใจ หน้าเข้าสู่ระบบจึงเป็นดีไซน์ ไม่ตรวจและไม่เก็บรหัสผ่าน

## ทำไมเลือกชุดเครื่องมือนี้ (ต่างจากค่าเริ่มต้นของพ้อยตรงไหน)

| เลือก | แทนที่ | เหตุผลและข้อแลกเปลี่ยน |
|---|---|---|
| Vite + React + TypeScript | Next.js | ระยะ A เป็นหน้าฝั่งเครื่องล้วน ไม่มี server จึงได้ไฟล์นิ่งที่เปิดจากที่ไหนก็ได้ และติดตั้งเป็นแอปออฟไลน์ได้ง่าย ย้ายเข้า Next.js ภายหลังได้เพราะหน้าเป็น React ล้วน เสียอย่างเดียวคือยังไม่มี server-side ซึ่งระยะ B ค่อยตัดสินใจพร้อมเรื่อง backend |
| CSS ของ Laong (คลาส `ld-*`) | Tailwind | design system กำหนดเป็น CSS พร้อม token อยู่แล้ว ใช้ตรงจะไม่เกิดสีหรือขนาดที่หลุดจากระบบ |
| localStorage (key `proto_*`) | Firebase | ระยะ A ยังไม่เชื่อม backend ของปลื้ม การเก็บในเครื่องทำให้ไม่มีข้อมูลทีมออกนอกเครื่อง |
| ฟอนต์จาก `@fontsource` | Google Fonts | ฟอนต์ติดไปกับแอป ไม่มี request ออกนอกเครื่อง |

## ไฟล์ไหนทำอะไร และข้อมูลไหลอย่างไร

```
หน้าจอ (src/pages) -> adapter (src/core/adapter.ts) -> สูตรต้นฉบับ (src/core/original/*.js)
        |                                                   (ห่อด้วย physics.gen.js ไม่แก้เนื้อไฟล์)
        v
ที่เก็บสถานะ (src/data/store.ts) -> localStorage (proto_*)
```

| ที่ | หน้าที่ |
|---|---|
| `src/core/original/` | สูตรต้นฉบับตรงตัว **ห้ามแก้** `scripts/gen-core.mjs` ตรวจ sha256 ก่อนห่อทุกครั้งที่ `dev`, `build`, `test` ถ้าไม่ตรงจะหยุด |
| `src/core/physics.gen.js` | ไฟล์ที่สร้างอัตโนมัติ ห่อสูตรไว้ในฟังก์ชันเดียว ไม่ต้องแก้ |
| `src/core/adapter.ts` | ชั้นเชื่อม ตรวจว่ากรอกครบและเป็นตัวเลข ส่งเข้า `PHYSICS` แล้วคืนผลพร้อมป้าย predicted และ unvalidated ค่าว่างไม่ถูกแปลงเป็น 0 |
| `src/config/synthetic.ts` | โปรไฟล์เครื่องตัวอย่าง วัสดุตัวอย่าง เกณฑ์ steady state ตัวอย่าง ค่าจริงของเจ้าของต้องมาแทนที่ไฟล์นี้ไฟล์เดียว |
| `src/data/` | ชนิดข้อมูล ที่เก็บสถานะ ร่างอัตโนมัติ และรันตัวอย่าง 7 รัน |
| `src/lib/` | ฟังก์ชันอ่านค่าจากรัน (steady state, predictionError, ความเสี่ยง) และส่งออก CSV, JSON, Word |
| `src/ui/` | ชิ้นส่วน UI ที่ห่อ `ld-*` (ป้ายที่มา, Metric, Field, Panel, กราฟ SVG) |
| `src/pages/` | Login, ภาพรวม, ก่อนทดลอง, ระหว่างทดลอง, หลังทดลอง, ประวัติ, รายงาน, ขั้นสูง, มุมมองอ่านอย่างเดียว, ดูผลก่อนรัน |
| `src/styles/app.css` | สิ่งที่ design system ยังไม่มี (หัวหน้า กราฟ ลายหยดละออง animation) ใช้ token เท่านั้น |
| `design-system/` | Laong design system จากแพ็ก (สำเนา) พร้อม component ที่เพิ่มใน `components/Chart` และ `components/Tile` |

## กฎข้อมูลที่ทำไว้แล้ว

- ค่าว่างแสดง "ยังไม่มีค่า" พร้อมป้าย Missing ทุกที่ (ตัวเลข ตาราง กราฟ) CSV ออกเป็นช่องว่าง JSON เป็น null
- ทุกตัวเลขมีป้ายที่มา 1 ป้าย (9 ชนิด) ผลทำนายติดป้าย Predicted พร้อมแถบ UNVALIDATED
- TS ไม่เท่ากับ °Brix: ใช้ Brix ได้เมื่อผู้ใช้เลือกเอง และติดป้าย Proxy ส่วน Pump % แปลงเป็น mL/min ด้วย Proxy
- ผล Target Tout เป็น "คำนวณ UNVALIDATED" เสมอ `recommendations` เป็น `[]` และ `operationallyApproved` เป็น `false` ตายตัว
- `predictionError` เป็น null จนกว่าจะมีค่าที่อ่านได้
- รายงานผูกกับรันเดียว ติ๊ก ✓ เฉพาะขั้นที่ทำจริง ผู้ใช้ข้ามขั้นได้
- ร่างบันทึกอัตโนมัติ เปิดใหม่มีแถบ "ใช้ร่างนี้" และ "ทิ้งร่าง"

## ส่วนที่เพิ่มรอบล่าสุด

- **ละอองต่อเนื่อง** (`SprayField` ใน `src/ui/droplets.tsx`) ขยับตลอดบนหน้าเข้าสู่ระบบและสถานะว่างของหน้าก่อนทดลอง ตามที่ผู้ใช้ขอ ซึ่งต่างจากข้อ 9 ของบรีฟที่ห้ามวนไม่หยุด จึงจำกัดไว้เฉพาะงานตกแต่ง: ใช้ CSS transform กับ opacity อย่างเดียว หยุดเองเมื่อแท็บไม่ได้เปิดอยู่ และหยุดเมื่อผู้ใช้ตั้ง reduced motion ถ้าพ้อยหรือปลื้มไม่ต้องการ ให้สลับกลับไปใช้ `DropletField` (เล่นครั้งเดียว) ได้ที่ `Login.tsx` และ `Pre.tsx`
- **ตัวเลือกแบบเลื่อนลง** (`Select` ใน `src/ui/overlay.tsx`) แทน `<select>` ของเบราว์เซอร์ทุกจุด ใช้คีย์บอร์ดได้ครบและเปิดปิดนุ่ม
- **ลิ้นชักตั้งค่าและช่วยเหลือ** (`src/app/SettingsDrawer.tsx`): เครื่อง, บอร์ดและกล้อง, ความหมายป้าย, เพิ่มเติม ทำให้หน้าภาพรวมสั้นลงโดยฟังก์ชันไม่หาย
- **บอร์ด ESP32** (`src/device/`): สถานะการเชื่อมต่อ ความหน่วง และสัญญาณสั่งกล้อง ปิดไว้เป็นค่าเริ่มต้น วิธีต่อและตัวอย่างโค้ดบอร์ดอยู่ที่ `docs/ESP32-LINK.md` และ `device/esp32/` ฝั่งเว็บลองกับบอร์ดจำลองในเครื่องแล้ว ฝั่งบอร์ดจริงยังไม่ได้ทดสอบ

## ที่ยังไม่ได้ทำหรือยังรอ

- ฟังก์ชันที่ต้องคัดลอกพฤติกรรมจากไฟล์ core ที่ไม่อยู่ในแพ็ก (doe.js, powder-optimizer.js, run-protocol.js, sequential-experiment.js, calibration.js) ทำเป็นแบบง่ายหรือ "ยังไม่เปิดใช้" และบอกไว้ในหน้าจอ: DOE ใช้ Latin hypercube ตัวอย่าง, สมดุลมวลแบบง่าย, เกณฑ์ steady state ตัวอย่าง, Suggested next run และ Pareto ยังไม่เปิดใช้, ปุ่ม Apply ของคาลิเบรตถูกล็อก
- ของใหม่ (Snap-to-Read, Machine ID, แดชบอร์ดผู้บริหาร, ฐานข้อมูลงานวิจัย, พยากรณ์คุณภาพผง, บัญชีผู้ใช้จริง) วางไว้ในดีไซน์พร้อมป้าย "ยังไม่เปิดใช้" ไม่มีตัวเลข
- การอ่านข้อมูลเก่าคีย์ `spraydry_*` ของแอปต้นฉบับยังไม่ทำ (ต้นแบบใช้ `proto_*` เท่านั้น)
- เรื่องที่รอปลื้มหรือพ้อยตัดสิน: ดูหัวข้อ 12 ของบรีฟ โดยเฉพาะนิยาม OBSERVED (ตอนนี้ใช้ตามที่บรีฟตั้ง และยังไม่ล็อก) การยืนยันว่าสมการไม่เปลี่ยน และการต่อ backend
